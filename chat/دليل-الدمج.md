# دليل دمج الدردشة داخل مستودع مدارك جو

هذا المجلد هو **النسخة الجاهزة للنقل** — الكود المصدري الكامل لمشروع الدردشة، معدّلة
لتعمل كقسم داخل الموقع الأم تحت المسار:

```
madrekjo.com/chat/
```

المشروع الأصلي في `Downloads\site-full` لم يُلمس — يبقى كما هو حتى تتأكد أن النسخة تعمل.

---

## 1) ماذا يوجد في هذا المجلد؟

| المجلد/الملف | الغرض |
| --- | --- |
| `src/`, `public/`, `supabase/`, `package.json`, `vite.config.*` ... | **الكود المصدري الكامل** للتطوير والبناء |
| `build-output/` | **مخرجات البناء النهائية الجاهزة** (تخدم المستعرض مباشرة) |
| `404.html` | ملف حاجز — **يُنسخ لجذر المستودع، وليس داخل chat** |
| هذا الدليل | خطوات الدمج |

---

## 2) خطوات الدمج (بالترتيب)

### الخطوة 1 — نسخ الكود
انسخ **محتوى هذا المجلد** (عدا `404.html` وهذا الدليل) إلى مستودع الموقع الأم تحت:

```
repo/chat/
```

فيتحول البنية إلى:
```
madrekjo.com/
├── 2009/
├── css/
├── js/
├── chat/              ← الدردشة (كود مصدري + ملفات تشغيل)
└── index.html
```

### الخطوة 2 — وضع ملفات التشغيل في مكانها الصحيح
GitHub Pages لا ينفّذ بناء، لذلك يجب أن تكون **ملفات البناء** موجودة فعلاً داخل `repo/chat/`:

- انسخ **محتوى** `chat/build-output/` إلى `repo/chat/` مباشرة
  (أي انسخ `index.html` و `assets/` و `favicon.ico` و `robots.txt` إلى جذر `chat/`).

> بديل: شغّل `npm install` ثم `npm run build` داخل `repo/chat/` — الناتج في `chat/dist/`
> انسخ محتواه إلى `repo/chat/` بنفس الطريقة.

### الخطوة 3 — ملف الحاجز
انسخ `404.html` إلى **جذر المستودع** (`repo/404.html`) وليس داخل `chat/`.
هذا ضروري حتى تعمل روابط تسجيل الدخول الراجعة مثل `madrekjo.com/chat/auth/callback`.

### الخطوة 4 — إعدادات Supabase (داشبورد فقط، لا توجد في الكود)
من https://supabase.com/dashboard → مشروعك `ofltanaffcxoobfvlkii` → Authentication → URL Configuration:

- **Site URL** ← `https://madrekjo.com`
- **Redirect URLs** ← أضف:
  - `https://madrekjo.com/chat/auth/callback`
- (اختياري) اترك رابط الدردشة القديم أو احذفه.

> بدون إضافة الرابط الجديد: تسجيل الدخول بـ Google سيرجع لرابط قديم أو يُرفض.

### الخطوة 5 — ربط زر "الدردشة الدراسية" في الموقع الأم
غيّر رابط القسم في هذه الملفات (5 ملفات):
- `2009/engineering.html`
- `2009/health.html`
- `2009/business.html`
- `2009/languages.html`
- `2010/index.html`

من:
```js
{ icon: '💬', text: 'الدردشة الدراسية', url: '../coming-soon.html', type: 'iframe', title: 'الدردشة الدراسية' },
```
إلى:
```js
{ icon: '💬', text: 'الدردشة الدراسية', url: '/chat/', type: 'iframe', title: 'الدردشة الدراسية' },
```

### الخطوة 6 — رفع للمستودع
```
git add .
git commit -m "دمج الدردشة داخل /chat"
git push
```
ثم افتح `madrekjo.com/chat/`.

## 3) التعديلات التي طُبقت على كود الدردشة (لتقف على كل شيء)

| الملف | التعديل |
| --- | --- |
| `vite.config.ts` | إضافة `base: "/chat/"` فتصير ملفات البناء `/chat/assets/...` |
| `src/App.tsx` | `BrowserRouter basename="/chat"` + نقل صفحة الدردشة الرئيسية من مسار `/chat` إلى `/` (لأن الدردشة أصبحت عند `/chat/`) |
| `src/components/Navbar.tsx` | روابط الدردشة من `/chat` إلى `/` |
| `src/pages/Admin.tsx`, `AdminReports.tsx` | إعادة التوجيه إلى `/` |
| `src/pages/Auth.tsx` | `redirectTo` أصبح يعتمد على `import.meta.env.BASE_URL` فيرجع إلى `/chat/auth/callback` تلقائياً |
| `src/pages/Notifications.tsx`, `src/components/NotificationBell.tsx`, `src/components/AdminReportsPanel.tsx`, `src/pages/AdminReports.tsx`, `src/pages/StaffMeeting.tsx` | روابط فتح المنشور من `/chat?post=...` إلى `/?post=...` |
| `src/pages/NotFound.tsx`, `src/pages/Index.tsx` | روابط مطلقة أصبحت نسبية |

**لم يتغير:** أي وظيفة (دردشة، جولات، جداول، إدارة، بروفايل، إشعارات...) ولا رابط
قاعدة البيانات `src/config/supabase-config.ts` (نفس القاعدة).

## 4) النقاط التي تعتمد على الدومين القديم

- **داخل الكود:** لا يوجد أي رابط للدومين القديم — كل الروابط ديناميكية
  (`window.location.origin`) وستعمل تلقائياً على الدومين الجديد.
- **في Supabase (خارج الكود):** Site URL و Redirect URLs (الخطوة 4 أعلاه) — هذا كل ما يحتاجه.
- **في الموقع الأم:** زر الدردشة (الخطوة 5).

## 5) تنبيهات مهمة

1. **إعادة البناء لاحقاً:** بعد أي تعديل، شغّل `npm run build` داخل `chat/` ثم انسخ محتوى
   `chat/dist/` إلى `chat/` (لتحديث `index.html` و `assets/`).
2. **تحديث `404.html`:** أسماء ملفات `assets/*` تتغير مع كل بناء (أسماء مجزأة hash).
   انسخ ملف `chat/dist/index.html` الجديد فوق `404.html` مع **إبقاء سكربت الحارس**
   الموجود في بداية `<head>`.
3. **مشاركة localStorage:** بعد الدمج يتشارك الموقع والدردشة نفس الـ origin
   (مطلوب ليعمل تسجيل الدخول). لا يوجد ما يمنعه، لكن اعلم أن بيانات الدردشة
   (توكن Supabase، الثيم...) في نفس مخزن المتصفح.
4. **الـ Service Worker للموقع الأم** (`sw.js`) يعمل كما هو — لا يحتاج تعديلاً،
   ويخزّن مؤقتاً ملفات `/chat/*` عند زيارتها.
5. **ملف `_redirects`** داخل البناء مخصص لمنصات Netlify/Cloudflare Pages؛ على
   GitHub Pages لا يعمل ولا يضر — اتركه.
